Checklist Gỡ lỗi (Debug Steps) 1/3 Hoàn thành
  • 1. Kiểm tra vòng đời Access Token Access token đã hết hạn 15 phút. Xác nhận client có tự động kích hoạt flow refresh token trước khi gửi request tới API bảo mật hay không.
  • 2. Bắt ngoại lệ ExpiredJwtException trong Filter Bọc khối try/catch trong JwtAuthenticationFilter để trả về HTTP 401 Unauthorized và mã lỗi ApiResponse("TOKEN_EXPIRED") thay vì để văng lỗi 500.
  • 3. Cấu hình Clock Skew phòng lệch giờ Bổ sung .setAllowedClockSkewSeconds(60) vào JwtParserBuilder để chấp nhận độ trễ đồng hồ 60 giây giữa các server và gateway.
Acceptance Criteria (Given - When - Then) 3 tiêu chí
  • AC-1: Đăng nhập thành công trả về token kép Given tài khoản tồn tại và mật khẩu hợp lệ, When POST /login, Then nhận HTTP 200 kèm access_token (15m) & refresh_token (7d).
  • AC-2: Sai mật khẩu trả về mã lỗi 401 Given mật khẩu không khớp, When POST /login, Then nhận HTTP 401 kèm ApiResponse lỗi chung để bảo mật.
  • AC-3: Khóa tài khoản sau 5 lần thất bại Given tài khoản bị nhập sai 5 lần, When thử lần thứ 6, Then nhận HTTP 423 Locked và thông báo thời gian khóa 15 phút.
Edge Cases (Trường hợp kiểm thử biên) 2 trường hợp
  • Edge-1: Payload rỗng hoặc sai cú pháp email Given request body rỗng hoặc email không có ký tự @, When POST /login, Then MethodArgumentNotValidException trả về 400 Bad Request.
  • Edge-2: Đăng nhập đồng thời vào ngưỡng lần 5 Given gửi nhiều request song song từ nhiều tab, Then bộ đếm Redis/DB phải đảm bảo tính atomic chống race condition.
